3 · Code layers (browser · shared · server · data · outside services · git)

The whole module by file. Labels updated on 30 Oct; the field-of-study, interest-area and suggestion routes are drawn in full in diagram 1.

How the sources link, in one line each

  • • O*NET-SOC job codes join skills, software, knowledge, work styles, activities and interest areas
  • • Field of study → jobs: ISCED-F code → CIP code (Statistics Canada) → O*NET-SOC (O*NET crosswalk); equal codes only, 118/124 fields
  • • Suggested skills: those jobs → what they list more often than all jobs (software ≥ 2 jobs; skills above the all-jobs average)
  • • Roles: O*NET snapshot (job titles) beside eMASCO titles; live O*NET first once a key exists
  • • Profile ids keep their source: onet:tech/el/ws/kn/dwa/ia · isced:code · onet|emasco occupation code

What is on and what is waiting

  • • ON: upload, form with search pickers, review, summary, O*NET 31.0, ISCED-F + CIP bridge, eMASCO, guest saving, 3 languages
  • • WAITING (owner keys): ONET_API_KEY, D1_*, R2_*
  • • OFF (owner choice): L3 RunPod embeddings, AI re-read provider (RunPod chat / Claude)
  • • Stored for matching, not used yet: isced_cip + cip_onet bridge, interest-area values (1–7), work-style values
  • • Next module: matching. It reads the saved profile (column 6). No old scoring
