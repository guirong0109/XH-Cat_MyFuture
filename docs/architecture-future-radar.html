Future Skills Radar — Round 1 Architecture

Branch claude/future-radar · real sources → one pure trend engine → versioned signals → Radar screens · no scores or rankings

How one refresh flows

  • • 1 Admin presses Refresh → fetch OpenAlex or DOSM
  • • 2 Validate: broken data is rejected, last good stays
  • • 3 Compare: same content → "checked, no new data"
  • • 4 One pure engine calculates trends and signals
  • • 5–6 Save write-once, then switch active.json atomically
  • • 7–8 API serves one version; screens show it with links

Guards that keep it honest

  • • Every number has a source link and dates
  • • Thin or broken comparisons say "Insufficient evidence"
  • • Possible structural breaks need admin review
  • • Field↔topic links count only after owner approval
  • • Judges work in demo/<session>/, never prod/
  • • No score, weight or ranking anywhere in Round 1
